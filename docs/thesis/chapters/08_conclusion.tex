\chapter{Conclusion and future work}
\label{ch:conclusion}

\section{Conclusion}
\label{sec:concl}

Multi-HMR reconstructs several complete human bodies from one image. My project builds on this framework with the
Anny body model, converted 3DPW labels and a smaller distilled student. I also added temporal filtering and landmark
alignment to improve the video outputs.

To train on real photos, I converted 3DPW's SMPL labels into Anny labels. The converter matches the joints of the two
body models, adds virtual torso joints and keeps one median shape per person and sequence. In an independent check the
converted joints lie a median \DataCheckJointsNew\,mm from 3DPW's, and some phenotypes are the same for every person
(Section~\ref{sec:data-limits}).

The ViT-B student trains on AnnyOne and converted 3DPW. It reuses the prediction heads of its ViT-L teacher, Final,
through a learned projector, and learns to imitate the teacher's features and outputs. Both models use consistent
head anchors and one fixed output rotation correction, which I analyse in the appendices. At inference only the
student and the Anny decoding layer run.

The student is cheaper: \StudentParams\,M parameters and \StudentGFLOPs\,GFLOPs against the teacher's \FinalParams\,M
and \FinalGFLOPs\,GFLOPs, and \StudentMsLFortyS{} against \TeacherMsLFortyS\,ms per forward pass on the L40S GPU. The
teacher is more accurate. On the AnnyOne holdout and the converted 3DPW test set its PVE was \FinalPVE{} and
\FinalThreeDPW\,mm, against \StudentPVE{} and \StudentThreeDPW\,mm for the student. So the student failed the 95\,\% rule I set
beforehand (Section~\ref{sec:res-student}). Its 3DPW PVE is lower than the \NAVERThreeDPW\,mm of the released
Multi-HMR-Anny, but only my models were trained on converted 3DPW.

I also trained the student for 60 epochs. The holdout PVE fell to \StudentSixtyPVE\,mm, but the 3DPW PVE moved only
from \StudentThreeDPW{} to \StudentSixtyThreeDPW\,mm, with no repeated runs to measure the variation on 3DPW
(Section~\ref{sec:res-training-length}). So longer training alone does not close the gap on real images, and I keep
the 30-epoch student. A sweep of the distillation temperature
from 1 to 8 changed the errors by at most \KDTPRange\,mm, no more than the variation between two runs of the same
setting, so the temperature is not the limit either (Section~\ref{sec:res-kd-temperature}).

On a walking clip of \VideoFrames{} frames, the student kept a tracked person in \VideoStudentMatched{} frames and the
baseline in \VideoBaselineMatched{} (Section~\ref{sec:res-video}). By eye, the filter made the motion steadier, and the
alignment improved the mesh's position and size, so it followed the person more closely. The network still works frame
by frame, and neither step is a learned temporal model (Section~\ref{sec:method-temporal}). The clip has no ground truth, so this shows
steadier output, not better 3D accuracy.

\section{Future work}
\label{sec:future}

\paragraph{Temporal evaluation and modelling.}
I would run the filter and the alignment on the 3DPW test sequences, whose converted labels exist at \DataLabelFps{}
frames per second, and measure PVE per frame against the raw student, so that steadiness and accuracy are measured
together. Then I would test clips with occlusion, a moving camera or several people, and report each frame rate
with its GPU, precision and input resolution. A learned temporal model (Section~\ref{sec:bg-temporal}) is a separate
project.

\paragraph{Accuracy at reduced cost.}
After the temperature sweep, I would try other weights for the distillation losses, other ways of transferring the
teacher's features and more real images per batch. A fair comparison also needs Multi-HMR-Anny fine-tuned on the same
3DPW data.

\paragraph{Real-image shape.}
To replace the constant phenotypes, I would use age-group labels, body measurements or more Anny fits on real photos.
Tests with children should keep two questions apart: can Anny make child proportions, and does the network recognise a
child in a photo?

\paragraph{Reliability and reproducibility.}
Each model comes from one run. I would repeat the runs, with uncertainty estimates and a larger holdout set, to see
which differences are real. A portable configuration with release checks would make the system easier to verify. I
have not run any of these.
